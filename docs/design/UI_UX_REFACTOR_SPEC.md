## 一、首先找到并读取已经安装的 UI Skill

开始 UI 工作之前，先检查当前 Zcode 环境及项目目录中已经安装的 Skill。

重点检查：

- Zcode 当前可以使用的 Skill。
- 项目根目录中的 Skill 配置。
- `.zcode/skills/`
- `.agents/skills/`
- `.claude/skills/`
- `.cursor/skills/`
- `skills/`
- `AGENTS.md` 及其他项目级 AI 规则文件。
- 其他已经配置的 UI/UX、Design QA、Design System 相关资源。

以上目录只是排查入口，不代表所有目录都一定存在。

重点识别以下类型的 Skill：

- UI/UX Design Audit
- Design QA
- Design System Checker
- UI Design
- Product Design
- Visual Design
- Accessibility Audit
- Responsive Design Audit

如果已经安装了 `design-qa` 或类似 Skill，必须实际读取其完整说明和配套文件，了解它的使用方法、检查标准、执行流程和输出要求。

不能只看到 Skill 名称就认为已经使用。

不能只读取一小段介绍就开始工作。

不能因为当前项目使用 Zcode，就忽略此前安装的通用 Skill。

### Skill 使用规则

1. 优先使用已经安装的相关 Skill，不要重复安装同类型工具。
2. 读取 Skill 的完整说明以及相关参考文件。
3. 按照 Skill 中规定的审计标准执行。
4. 将 Skill 的设计规范与 DIGITAL TECH MUSEUM 的产品定位结合。
5. 不要机械套用通用后台管理系统的设计风格。
6. 如果多个 Skill 能力互补，可以组合使用。
7. 如果 Skill 之间存在冲突，先分析原因，再选择适合本项目的方案。
8. 不要只把 Skill 当作检查清单，必须将检查结果落实到实际 UI 代码中。

如果当前环境无法找到或读取该 Skill，不允许假装已经调用。应明确记录缺失情况，检查现有项目文档中是否有 Skill 的本地副本，并在能力允许的范围内完成 UI 审计与重构。

## 二、对整个项目进行 UI/UX 全面审计

在修改代码之前，先完整检查当前界面。

不要只检查首页。

应尽可能覆盖：

- 项目首页。
- 展馆入口。
- 导航系统。
- 设备列表。
- 设备详情。
- 3D 展示区域。
- 设备控制面板。
- 爆炸拆解界面。
- X-Ray 界面。
- 部件信息面板。
- 技术档案。
- 弹窗。
- 抽屉。
- 卡片。
- 标签。
- 按钮。
- 表单。
- 加载状态。
- 空状态。
- 错误状态。
- 移动端界面。

以项目实际存在的页面为准，不要为了满足清单而虚构不存在的页面。

### 2.1 视觉设计审计

检查：

- 页面整体视觉风格是否统一。
- 主色和辅助色是否协调。
- 是否存在颜色滥用。
- 字体大小和字重是否合理。
- 标题、正文、辅助信息的层级是否清晰。
- 页面留白是否合理。
- 卡片、面板和容器是否一致。
- 圆角是否统一。
- 阴影和边框是否统一。
- 玻璃质感是否真实自然。
- 背景层次是否合理。
- 图标风格是否一致。
- 3D 场景和 UI 是否融为一体。
- 是否存在廉价、过时或模板化的视觉效果。

### 2.2 交互体验审计

检查：

- 用户是否容易理解当前页面。
- 核心功能是否容易找到。
- 按钮是否有明确的操作反馈。
- 面板展开和收起是否自然。
- 页面切换是否流畅。
- 操作是否存在多余步骤。
- 控件状态是否清晰。
- 是否存在功能入口重复。
- 是否存在无效按钮。
- 是否存在交互逻辑不一致。
- 是否存在遮挡 3D 模型的问题。

### 2.3 响应式审计

重点检查：

- 桌面端布局。
- 常见笔记本尺寸。
- 平板布局。
- 手机竖屏。
- 手机横屏。

特别关注 3D 模型展示区域、侧边栏、浮动控制面板、弹窗和底部操作栏。

不能只保证 PC 看起来漂亮。

### 2.4 可用性和可访问性审计

检查：

- 文字与背景的对比度。
- 按钮点击区域。
- 图标是否容易理解。
- 键盘操作是否合理。
- 焦点状态是否清楚。
- 动画是否影响使用。
- 用户是否可以及时退出弹窗和面板。
- 信息是否存在过度堆叠。

### 2.5 审计结果必须留档

建立一份独立的审计文档，例如：

`docs/design/UI_UX_AUDIT.md`

根据当前阶段创建相应的阶段档案，例如：

`docs/phases/PHASE_XX_UI_UX_AUDIT_AND_REFACTOR.md`

审计文档必须记录：

- 审计范围。
- 使用的 UI Skill。
- 实际读取的 Skill 文件。
- 当前 UI 结构。
- 当前视觉问题。
- 当前交互问题。
- 响应式问题。
- 可访问性问题。
- 问题优先级。
- 推荐改造方案。
- 需要重点重构的页面。
- 不应该被破坏的现有功能。

每个问题应尽可能关联具体页面、组件或文件，不要只写「视觉不够高级」「设计不够统一」这种没有执行价值的结论。

## 三、重新建立统一的设计系统

审计完成后，不要立刻逐个修改页面。

先建立一套适合 DIGITAL TECH MUSEUM 的统一 Design System。

建议建立或更新：

- `docs/design/DESIGN_SYSTEM.md`
- `docs/design/UI_GUIDELINES.md`
- `docs/design/INTERACTION_GUIDELINES.md`

根据项目实际技术结构，决定是否需要对应的设计 Token 文件。

### 3.1 视觉定位

整体方向：

**高端数字科技博物馆 + 未来科技展馆 + 沉浸式 3D 探索空间。**

希望呈现：

- 高级感。
- 空间感。
- 未来科技感。
- 精致的细节。
- 清晰的信息层次。
- 强烈但克制的视觉表现。
- 有辨识度的品牌风格。

不要把项目设计成普通 SaaS 后台。

不要把项目设计成传统电商页面。

不要直接套用常见 AI Dashboard 模板。

### 3.2 建立 Design Tokens

统一管理：

**颜色体系**

- 主背景。
- 次级背景。
- 面板背景。
- 主色。
- 辅助色。
- 强调色。
- 正文颜色。
- 辅助文字颜色。
- 边框颜色。
- 状态颜色。
- 遮罩颜色。

**排版体系**

- Display。
- Heading。
- Subtitle。
- Body。
- Caption。
- Label。
- 数据展示文字。

**尺寸体系**

- 页面最大宽度。
- 内容间距。
- 栅格间距。
- 页面内边距。
- 组件内边距。
- 面板宽度。
- 弹窗尺寸。

**视觉效果**

- 圆角规范。
- 阴影规范。
- 边框规范。
- 玻璃模糊等级。
- 透明度规范。
- 发光效果。
- 过渡效果。
- 动画时长。

所有页面优先使用统一 Token。

不要出现每个组件随意定义一套颜色、间距和圆角的情况。

### 3.3 组件设计规范

统一：

- Button。
- Icon Button。
- Card。
- Panel。
- Modal。
- Drawer。
- Tooltip。
- Tabs。
- Badge。
- Input。
- Select。
- Loading。
- Empty State。
- Toast。
- Navigation。

根据项目实际组件体系决定重构方式。

优先复用和升级现有组件，不要无意义地创建大量重复组件。

## 四、重点重构 3D 博物馆工作空间

这是 DIGITAL TECH MUSEUM 与普通网站最大的区别。

界面不应该只是简单地把几个面板摆放在 3D Canvas 周围。

需要重新思考：

**如何让 UI 成为 3D 展示体验的一部分，而不是 3D 场景的干扰物。**

重点审查和重构：

### 4.1 3D 主展示区域

- 给模型足够的视觉空间。
- 减少无意义的 UI 遮挡。
- 优化场景与信息面板的关系。
- 优化背景和环境氛围。
- 建立清晰的操作提示。
- 让模型成为整个页面的视觉中心。

### 4.2 控制面板

重新规划：

- 视角控制。
- 模型旋转。
- 缩放。
- 复位。
- 拆解模式。
- X-Ray 模式。
- 剖切模式。
- 部件选择。
- 展示模式切换。

操作入口应清晰，并根据功能重要程度确定视觉权重。

避免把所有按钮都做成相同大小、相同颜色和相同样式。

### 4.3 设备信息面板

重新设计：

- 设备名称。
- 品牌信息。
- 型号。
- 重要参数。
- 技术亮点。
- 结构介绍。
- 当前选中部件。
- 相关知识入口。

让信息有合理的层级和阅读节奏。

不要把设备的所有信息一次性堆在屏幕上。

### 4.4 部件交互界面

重点考虑：

- 当前选中部件的视觉反馈。
- 部件名称。
- 部件定位。
- 部件说明。
- 相关技术知识。
- 结构层级。
- 返回整机视图。

部件信息界面必须与模型操作保持一致。

### 4.5 沉浸式模式

可以探索：

- 极简展示模式。
- 全屏 3D 模式。
- 设备信息模式。
- 拆解实验模式。
- 技术讲解模式。

不同模式应有明显但自然的状态差异。

## 五、实际 UI 重构实施路线

不要一次性随意修改全部页面。

采用分阶段重构方式，每个阶段建立独立文档。

### UI 阶段 A：设计审计与问题清单

完成：

- UI Skill 阅读。
- 全站 UI 检查。
- 页面和组件清单。
- 视觉问题分类。
- 交互问题分类。
- 响应式问题分类。
- 形成审计文档。

### UI 阶段 B：统一设计系统

完成：

- 设计方向确定。
- Design Tokens。
- 色彩规范。
- 字体规范。
- 间距规范。
- 组件规范。
- 动效规范。
- 玻璃质感规范。

### UI 阶段 C：全局框架与导航重构

重点优化：

- 全局布局。
- 导航。
- 页面容器。
- 背景体系。
- 页面过渡。
- 全局视觉一致性。

### UI 阶段 D：核心页面重构

优先处理最能代表产品品质的页面：

- 首页。
- 展馆入口。
- 设备列表。
- 设备详情。

以实际存在的页面为准。

### UI 阶段 E：3D 工作空间重构

重点优化：

- 3D 展示布局。
- 操作控制区。
- 信息面板。
- 拆解界面。
- 部件信息。
- 沉浸式模式。

### UI 阶段 F：通用组件与细节升级

优化：

- 卡片。
- 按钮。
- 弹窗。
- 抽屉。
- 标签。
- Tooltip。
- Loading。
- Empty State。
- Toast。
- 各类状态反馈。

### UI 阶段 G：移动端专项重构

专门针对小屏幕重新设计布局和交互。

不要只是把桌面端面板压缩到手机屏幕里。

### UI 阶段 H：最终 Design QA

再次使用已经安装的 UI Skill 进行复查。

对照首次审计结果，检查问题是否真正解决。

发现问题后继续修正，直到达到合理的验收标准。

每个 UI 阶段分别建立独立文档，禁止把所有 UI 重构过程堆在一个 MD 文件里。

## 六、严格保护现有业务与 3D 能力

本次 UI 重构的重点是表现层和交互体验，不是推翻现有产品架构。

除非经过明确评估，否则：

1. 不重写 Three.js 核心引擎。
2. 不更换现有模型文件。
3. 不修改设备原始数据。
4. 不删除现有功能。
5. 不改变已经正确工作的业务逻辑。
6. 不破坏模型加载机制。
7. 不破坏 Raycaster 部件拾取。
8. 不破坏模型爆炸拆解能力。
9. 不破坏 X-Ray 和 Clip 功能。
10. 不破坏相机控制和视角管理。
11. 不擅自引入新的后端服务。
12. 不擅自引入付费 API。

允许在确有必要时：

- 重构 Vue 页面结构。
- 拆分复杂 UI 组件。
- 整理 CSS / SCSS。
- 统一设计变量。
- 重构布局系统。
- 优化组件状态管理。
- 调整面板层级。
- 优化交互反馈。
- 改进动效。
- 建立统一组件规范。

如果 UI 改动需要影响 3D 交互逻辑，先明确影响范围，确保原有能力仍然正常。

## 七、视觉验收与迭代要求

不能只凭代码检查判断 UI 重构已经完成。

尽可能启动实际项目，通过浏览器或当前可用的界面预览能力进行检查。

在条件允许时，保存重构前后的截图。

至少覆盖：

- 桌面端首页。
- 桌面端设备详情。
- 桌面端 3D 工作空间。
- 移动端首页。
- 移动端设备详情。
- 移动端 3D 工作空间。

没有截图或真实界面验证能力时，应明确标注未完成的视觉验证，不能伪造截图和测试结论。

### 最终验收标准

**视觉统一性**

- 页面视觉语言统一。
- 颜色体系统一。
- 字体层级清晰。
- 间距合理。
- 组件风格一致。

**产品辨识度**

- 能体现数字科技博物馆的定位。
- 不是普通后台模板。
- 3D 模型是视觉主体。
- 有自己的视觉特色。

**交互体验**

- 操作入口明确。
- 状态反馈清楚。
- 面板布局合理。
- 不存在明显遮挡。
- 页面切换自然。

**响应式体验**

- 桌面端正常。
- 移动端布局合理。
- 触摸操作正常。
- 小屏幕没有明显溢出。

**功能完整性**

- 原有业务功能正常。
- 模型加载正常。
- 部件拾取正常。
- 拆解功能正常。
- X-Ray 正常。
- 剖切正常。
- 相机控制正常。

**代码质量**

- 组件职责合理。
- 没有明显重复实现。
- 样式管理清晰。
- 没有引入不必要依赖。
- 没有明显性能退化。

最终应再次使用 UI Skill 完成 Design QA，并记录剩余问题。

## 九、现在开始执行

现在请把 UI 重构作为 DIGITAL TECH MUSEUM 的一项重点工作。

先找到并读取已经安装的 UI Skill。

然后进行完整的 UI/UX 审计，建立问题清单和设计系统，再按照阶段执行实际界面重构。

我不希望你只是把界面改成深色、增加玻璃效果、增加渐变和动画。

我希望你真正从产品设计角度重新审视整个界面：

- 哪些页面需要重新布局？
- 哪些组件应该统一？
- 哪些操作流程可以简化？
- 哪些信息应该重新组织？
- 哪些 UI 已经过时？
- 3D 展示和界面如何更好地融合？
- 如何让整个博物馆的体验更完整？

**大胆优化，但不要盲目推翻。**

不要只输出审计报告，要真正落地重构。

完成一个 UI 阶段后，主动执行下一阶段，不需要等待我每次发送"继续"。

最终目标：

让 DIGITAL TECH MUSEUM 的 UI 从目前的实现状态，进化成一套真正具有产品级品质、统一设计语言、沉浸式体验和长期可维护性的界面系统。
