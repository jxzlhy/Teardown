## 1. 现状实测（审计取证口径）

| 指标 | 实测值 |
|---|---|
| 1440×900 首屏内可交互元素 | **仅 6 个**（顶部导航 5 + 双厅切换） |
| 搜索框（`.filter-search`）位置 | **y≈1366**——在 900px 折叠线下约 1.5 屏 |
| 第一张展品卡片绝对位置 | **y=1366** |
| 门厅滚动容器总高 | `.hub` scrollHeight ≈ 19086px |
| 首屏可见内容 | 牌记（馆名巨字 + VOL 标语）+ 5 项统计 + 焦点展台（FOCUS 轮播） |

**根因**：门厅按「展览序厅」叙事设计（牌记 → 焦点展台 → 常设展标题 → 继续拆解 → 筛选/搜索 → 卡片），带明确目标的用户（「我要看 Mavic 3」）必须滚动约 1.5 屏才见到搜索。

## 2. 目标指标（任一候选的验收口径）

1. 1440×900 首屏（y < 900）内可交互元素 **≥ 3 个**（至少含：搜索框、一个品牌/类别入口）。
2. 搜索框中心 y **< 900**。
3. 序厅叙事保留（馆名/标语/焦点展台不被删除，只重排或压缩）。
4. 双厅、移动端（390×844）、日/夜厅、`verify:contrast` 0 不达标、smoke 全绿——五项回归不回退。
5. 移动端首屏不做本项改动（竖屏 hero 已是紧凑双行，搜索可达性问题另列）。

## 3. 候选 A —— 序厅压缩式（保守）

**思路**：不动信息架构，只压缩 hero 区垂直尺寸并把「筛选/搜索主行」上移。

```
┌──────────────────────────────────────────────────┐
│ 导航条（现状不变）                                  │
│ 牌记（馆名 clamp 降档 ~30%）+ 统计（单行化）  │ 焦点展台
│ （hero 两栏并排，总高 ≤ 60vh）                 │ （右侧，
│──────────────────────────────────────────────────│  不变）
│ 继续拆解 · RECENT chips（现状）                     │
│ 搜索框 + 收藏 + 筛选 chips（filter-main 上移至此）  │
│──────────────────────────────────────────────────│
│ 常设展标题 + 卡片网格（y≈850 起卷）                 │
└──────────────────────────────────────────────────┘
```

- **hero 改两栏**：`.hub-hero` 从上下堆叠改为 grid 两列（左牌记/右展台），hero 总高从约 78vh 压到 ≤60vh。
- **filter-main 上移**：把「继续拆解 + filter-main」两行提到 `hub-sect` 之前（DOM 移动，非重写）。
- **搜索框**：样式不变（复用现有 `.filter-search` pill 形态）。

| 维度 | 评价 |
|---|---|
| 改动面 | 小（CSS 布局 + 一段 DOM 顺序，无新组件） |
| 叙事 | 完整保留（序厅→焦点→检索→网格动线不变） |
| 焦点展台 | 尺寸略缩（右栏 55% 宽），展示性轻微让步 |
| 移动端 | isNarrow 分支已存在，影响可控 |
| 风险 | 低——不新增状态/组件，纯布局 |
| 预估首屏可交互 | 搜索框 y≈820 + RECENT chips + 筛选 chip 若干 → **≥5 个** ✓ |

## 4. 候选 B —— 并排发现式（激进）

**思路**：把「发现能力」做成首屏一等公民——hero 区并排压缩，其下新增一条**发现栏**（搜索 + TOP 品牌 + 类别入口三组合一）。

```
┌──────────────────────────────────────────────────┐
│ 导航条（现状不变）                                  │
│ 牌记（左 45%，紧凑）         │ 焦点展台（右 55%）    │
│──────────────────────────────────────────────────│
│ 发现栏：[搜索框 40%] [品牌 chips ×8 横滑] [分类 ▾]  │ ← 新组件
│──────────────────────────────────────────────────│
│ 继续拆解 · RECENT chips                            │
│ 常设展标题 + 卡片网格（y≈780 起卷）                 │
└──────────────────────────────────────────────────┘
```

- **发现栏**（新组件 `discovery-bar`）：搜索框（复用 filter-search）+ **TOP 8 品牌 chips**（按馆藏数排序，点击即设品牌筛选并滚动到网格）+ **类别下拉**（现有 filter-groups 的收敛入口）。
- 常设展筛选行保留原位（深度筛选不受影响）；发现栏是**快捷入口**，与深度筛选并存。

| 维度 | 评价 |
|---|---|
| 改动面 | 中（新组件 + hero 两栏 + 筛选联动） |
| 叙事 | 序厅保留但被「发现栏」打断——展览感让步于工具感 |
| 焦点展台 | 同 A 缩幅 |
| 移动端 | 发现栏需单独竖排适配（成本+1） |
| 风险 | 中——新组件含状态联动（品牌 chip ↔ 筛选 store），需回归品牌筛选全路径 |
| 预估首屏可交互 | 搜索框 + 8 品牌 chips + 分类入口 → **≥10 个** ✓✓ |

## 5. 取舍与建议

| | A 序厅压缩式 | B 并排发现式 |
|---|---|---|
| 首屏可交互 | ≥5 | ≥10 |
| 展览叙事完整度 | 高 | 中（被打断） |
| 改动面/风险 | 小/低 | 中/中 |
| 移动端成本 | 低 | 中 |
| 深度筛选保留 | 原位不动 | 原位不动（并存） |
| 对「专注看某台设备来馆」的用户 | 搜索一次到位 | 搜索+品牌双路 |

- **若馆方重视展览叙事**（序厅是产品记忆点）：选 **A**。
- **若馆方把「快速找到设备」当首要目标**（工具属性优先）：选 **B**。
- **混合方案 A+**（若需要折中）：按 A 实施，但把 A 的 filter-main 中**品牌 chips 组**横滑露出（不新增组件，把现有品牌筛选组提升为始终可见的首行）——首屏可交互≈7，成本≈A。
