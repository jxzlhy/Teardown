## 2. 核心发现（V3 必须解决的根因）

### F1 日厅是"覆盖补丁层"，不是主题系统（§10.3 违反）
- 事实：`html[data-hall="day"]` 选择器覆盖约 200+ 行集中在 `src/style.css` 尾部（~L1075 起），逐组件改色（`.chip`/`.card`/`.hub-nav`…），且混有 `#1c2836/#4a5b6d/#546577` 等**token 外硬编码**。
- 后果：任何新组件默认夜色，日厅必须逐个追补（2026-11-01 连补 ~80 条即此症状）；割裂感来自"每个组件各自被翻译了一遍"。
- V3 方案：语义 token 层（`--surface-*/--ink-*/--line-*` 等）由 `data-hall` 翻转取值，组件只消费语义 token；夜厅取值=现值（保证零回归），日厅在 token 层统一重设计。

### F2 卡片缩略图只有夜厅渲染（日厅割裂的最大单因）
- 事实：`lobby-day-top.png` 日厅网格全部卡片图是深夜底+青色展台辉光渲染，白卡+深图拼贴。
- V3 方案：缩略图管线产出**日/夜两套**（`render-thumbs.mjs` 已具备离屏渲染能力，增加日厅布光参数集），或至少去掉缩略图内强"夜厅签名"（青色辉光）改为中性影棚底。方向决策在 Phase 2 一并验证。

### F3 展台（日厅）无空间层次（§09 六层全缺）
- 事实：`workspace-day.png`——底座为纯白扁圆盘，无厚度/无刻度/无同心结构；模型接触关系含糊（悬浮感）；顶栏白底上近不可见（对比度失效）；地面网格线过粗抢戏。
- 夜厅底座（`workspace-night.png` 上部圆墩）已有圆墩+accent 环圈雏形（cc590f4），但同样缺刻度层/厚度层/坐标语义分层。
- V3 方案：按 §09 六层结构重建 `previewScene/engine` 展台几何（Three.js 几何体，非 CSS），双厅共享几何、只切材质与光照（§10.3）。

### F4 引擎双厅光照切换已存在（沿用，不重造）
- `setHallMode` 渐变、`floatSlots` 浮层栈、`data-hall` CSS 驱动均已落地（V2 第二章）；主题切换无闪屏/不重载模型已验证。V3 只做材质级扩展，不动状态管理。
