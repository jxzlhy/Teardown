# 2. V4.0 产品定位

V3.0 解决“如何生成机械模型”。V4.0 解决：
- 机械由哪些部件组成？
- 部件之间如何连接？
- 哪些部件会运动？
- 一个部件的运动如何影响其他部件？
- 机械在不同工作状态下如何变化？
- 用户如何观察内部结构？
- 用户如何理解工作过程？
- 模型如何被检查、评价、修复和复现？

体验升级为：

**观察 → 选择 → 理解 → 运行 → 拆解 → 对照 → 探索。**

格物馆同时管理：
- `REAL OBJECTS`：真实产品、设备和机械。
- `GENERATED OBJECTS`：程序化生成的虚构机械、概念机械和演示模型。

两类对象尽可能复用统一 Viewer、相机、零件选择、拆解、剖切、动画和元数据系统，但必须保留来源与可信度区别。概念模型不得标记为真实工程设备。

# 3. 六大核心系统

1. **Mechanism Graph 机械关系系统**：描述零件之间的连接、约束和传动关系。
2. **Kinematics & Motion 运动学演示系统**：让机械按照可解释的规则运行。
3. **Interactive Exploration 交互式结构探索**：剖切、局部拆解、隐藏、隔离、标注和零件追踪。
4. **Operating Principles 工作原理演示**：把机械动作转化为清晰的步骤和说明。
5. **Model QA & Diagnostics 模型质量诊断**：发现结构、坐标、几何、映射和运动问题。
6. **Mechanical Workbench 机械实验台 UI/UX**：把能力整合成一致、易用、视觉统一的体验。

先完成基础架构，再逐项深入，不要求一次性全部达到终极形态。

# 4. 机械关系系统 — Mechanism Graph

## 4.1 目标
建立可描述机械部件关系的数据结构，使系统知道零件不只是“放在一起”，而是具有固定、旋转、滑动、啮合、支撑或传动等关系。

## 4.2 关系类型
按项目需要逐步支持：
- `fixed`：固定连接。
- `revolute`：转动副。
- `prismatic`：移动副。
- `slider_crank`：曲柄滑块关系。
- `gear_mesh`：齿轮啮合。
- `belt_drive`：带传动。
- `shaft_coupling`：轴系耦合。
- `bearing_support`：轴承支撑。
- `linkage`：连杆机构。
- `visual_only`：仅用于视觉组织，不代表真实机械约束。

## 4.3 关系数据
每条关系至少包含稳定 ID、关系类型、关联零件 ID、连接锚点/局部坐标、轴线/方向、约束参数、运动参数、可视化标记和来源/可信度说明（适用时）。

## 4.4 关键要求
- 关系引用稳定零件 ID，不能依赖显示名称。
- 父子装配关系和机械运动关系必须区分。
- 不能把所有零件挂在一个父节点下就认为建立了机械关系。
- 关系数据可序列化、可校验、可调试。
- 关系变化后，运动和交互同步更新。
- 尚未实现真实约束的关系明确标记为视觉演示。

关系辅助线、连接点、旋转轴和传动链路默认克制，仅在用户开启工程辅助模式时出现。

# 5. 运动学与机械运行演示

## 5.1 统一运动系统
实现统一时间轴、播放/暂停、重置、播放速度、循环播放、关键状态标记、多部件同步，以及页面失焦和场景卸载时的资源管理。

运动系统由统一时钟驱动，避免每个零件各自使用不一致的动画循环。

## 5.2 V8 发动机
审计并升级 V3.0 已有实现：
- 曲轴旋转。
- 活塞往复。
- 连杆与曲柄销、活塞销保持连接关系。
- 左右气缸列方向和夹角正确。
- 多缸相位差可理解。
- 展示工作循环阶段。
- 支持慢速、正常速度、暂停关键位置、单缸观察。
- 可准确计算时才显示曲轴转角或进度。

如果没有实现真实燃烧、压力和热力学过程，不得显示伪造数据；可称为“概念工作循环示意”。

## 5.3 涡扇发动机
- 风扇级旋转。
- 压气机级旋转。
- 不同轴系转速关系可配置。
- 涡轮级与对应轴系关联。
- 外壳保持静止。
- 叶片旋转方向正确。
- 不允许整个发动机无差别旋转。

未实现 CFD 时，不得将粒子动画描述为真实流场仿真，只能称为“气流路径示意”。

## 5.4 科幻机械
虚构机械也必须有内部规则：输入部件、传动路径、输出部件、工作状态和状态过渡。可以有非现实构造，但不允许所有部件随机旋转、闪烁或伸缩来制造科技感。

# 6. 交互式结构探索

## 6.1 基础能力
尽量复用现有 Viewer，支持：
- 整机视图。
- 零件选中。
- 零件隔离（Isolate）。
- 单零件/子装配体隐藏与显示。
- 一级拆解和深度拆解。
- 一键复位。
- 剖切面。
- 局部剖切（技术可行时）。
- 透明/X 光辅助模式。
- 结构关系显示。
- 零件定位与相机聚焦。
- 零件名称和说明。

## 6.2 剖切要求
剖切不是简单将整个模型透明化：
- 剖切平面位置可调。
- 剖切方向可切换。
- 模型与剖切平面关系清楚。
- 适用时支持方向反转。
- 剖切与零件选择不冲突。
- 内部结构仍可辨认。
- 退出后恢复原始材质和显示状态。

若当前渲染技术不支持可靠的截面封口，必须说明限制，不得伪造完整实体截面。

## 6.3 零件定位与追踪
用户选择零件时，高亮对应对象、显示信息、聚焦视角、定位所属装配体，并在有关系数据时显示相连零件及其运动作用。

零件列表、3D 网格、关系图和信息面板必须引用同一稳定 ID，不能出现“列表选中 A，实际高亮 B”。

# 7. 工作原理演示系统

## 7.1 目标
把复杂机械变成可逐步理解的交互演示。

V8 示例：
1. 观察整机布局。
2. 展示曲轴。
3. 展示连杆与活塞。
4. 启动曲轴。
5. 观察活塞往复。
6. 对照多个气缸的运动差异。
7. 拆解查看部件。

涡扇示例：
1. 从进气口观察。
2. 展示风扇级。
3. 展示压气机级。
4. 展示燃烧室示意。
5. 展示涡轮级。
6. 观察轴系传动。
7. 查看外涵道与排气路径。

## 7.2 演示步骤数据
每个步骤包含步骤 ID、标题、简短说明、目标零件 ID、相机建议、辅助信息、动画状态和退出/下一步行为。

步骤必须对应模型真实存在的零件。缺少部件时不能虚构高亮目标。

## 7.3 交互
支持上一步/下一步、自动播放/暂停、退出、步骤进度。用户手动旋转模型后，演示逻辑不得失控；退出时恢复合理状态，不留下错误高亮或隐藏零件。

文案必须区分事实、概念说明和虚构设定，不编造工程参数。

# 8. 模型质量诊断与修复闭环

## 8.1 诊断类别

**结构：** 零件 ID 重复、父子关系循环、关键零件脱离、关系引用失效。  
**坐标：** NaN/Infinity、异常缩放、偏离主体、模型中心不合理、初始装配冲突。  
**几何：** 空几何、法线异常、明显穿插、重复面/闪烁风险、异常包围盒、面数过高。  
**运动：** 动画引用失效、运动轴缺失、运动范围异常、部件脱离连接点、复位失败。  
**展示：** 初始视角不可见、模型被 UI 遮挡、选中映射错误、拆解后零件飞出视区。

## 8.2 诊断分级
- `ERROR`：功能错误或模型无法正确展示。
- `WARNING`：可能存在结构、视觉或性能问题。
- `INFO`：优化建议。
- `UNVERIFIED`：证据不足，不能判断。

每条诊断说明问题对象、发现依据、影响范围、建议方案、自动修复可能性和修复风险。

## 8.3 AI 优化原则
- 低评分不等于授权自动修改。
- 诊断建议不等于真实证据。
- 无可靠来源的结构问题标记待核实。
- 不得凭空增加真实设备零件。
- 不得混合不同型号结构。
- 修改前备份，优先在副本/分支修复。
- 保留修改前后差异。
- 验证通过后才建议合并。
- 必须有回滚路径。

# 9. 机械实验台 UI/UX 重构

## 9.1 设计目标
主模型始终是视觉中心；控件克制但入口清晰；信息分层；与格物馆现有设计总览统一；昼夜主题完整适配；动效自然；兼顾桌面、平板和移动端。

不要把更多按钮塞进详情页，也不要用发光、渐变、粒子和玻璃效果掩盖布局问题。

## 9.2 建议交互模式
- `VIEW / 观察`：整机旋转、缩放、视角、全角度观察。
- `EXPLORE / 探索`：零件选择、隔离、隐藏、信息和关系。
- `MOTION / 运行`：播放、暂停、速度、关键状态。
- `SECTION / 剖切`：剖切面、方向、位置、透明辅助。
- `ASSEMBLY / 装配`：整机、子装配体、爆炸拆解、复位。
- `GUIDE / 原理`：分步骤讲解、镜头、零件高亮。

这些不一定做成六个大 Tab。按现有空间选择工具栏、侧边面板或情境菜单，不为满足名称而强行增加按钮。

## 9.3 Overlay 与状态管理
- Tooltip 不得被已打开菜单遮挡。
- 同时避免多个无序浮层。
- 菜单打开、切换、关闭和点击外部行为一致。
- 屏幕边缘自动调整方向。
- 触屏不依赖 hover。
- 键盘操作提供焦点状态。
- 选中、运动、拆解、剖切状态反馈清晰。
- 切换工具不重置相机、模型或当前零件。

## 9.4 3D 空间布局
协调主模型、展台底座、左侧零件导航、底部工具栏、坐标辅助装置、右侧信息面板和演示步骤面板。组件不能争夺空间或遮挡模型关键部位。坐标辅助装置必须准确反映模型方向，不能只是装饰性雷达圆环。

## 9.5 白天/夜间主题
白天：明亮、通透、自然采光；暖白、象牙白、浅灰有层次；卡片、边框、阴影和玻璃面板统一；模型不应过曝，金属材质保留质感。

夜间：深灰、墨黑、深蓝灰，不使用整块纯黑；环境光克制，重点照明突出机械；内部结构清楚，材质差异可辨。

切换时不得重新加载模型、重置相机或丢失选中/拆解/运动状态；UI 与 Three.js 灯光同步；过渡平滑无闪屏。

# 10. 完整用户流程验收

至少完成一条端到端流程：
1. 从展品列表打开机械。
2. 显示整机与基础信息。
3. 进入探索模式。
4. 选择一个零件。
5. 高亮并显示说明。
6. 查看它与其他部件的关系。
7. 进入运动模式。
8. 播放机械运动。
9. 暂停在关键状态。
10. 切换剖切或局部拆解。
11. 观察内部结构。
12. 进入工作原理引导。
13. 逐步讲解运动关系。
14. 退出并恢复整机状态。

不得出现状态冲突、错误高亮、模型重载、相机突然跳变或工具栏失效。

# 11. 首批验证对象与后续扩展

优先选取 V3.0 中实际存在且结构最完整的：
- V8 发动机。
- 涡扇发动机。
- 科幻复合动力核心。

先选择一个标杆模型跑通机制系统，再推广到其他模型。

后续候选：变速箱、差速器、曲柄滑块机构、齿轮传动箱、机械臂、液压/气动机构示意、旋转机械与泵、虚构多级动力传动系统。

不要只为数量增加模型。每增加一种机械，先验证是否复用已有关系、运动、拆解和讲解系统。

# 12. 性能、稳定性与兼容性

根据项目真实目标设备建立基线，不编造性能承诺。监测首屏加载、模型生成耗时、模型切换耗时、帧率、Draw Calls、三角面数量、材质数量、纹理占用、GPU 资源释放和连续操作后的内存增长。

生命周期要求：
- 组件卸载时停止动画。
- 场景切换时清理监听器。
- 几何体和材质按所有权释放。
- 共享资源不能被错误重复销毁。
- 连续生成模型不累积旧资源。
- 剖切、拆解和运动退出时恢复原始状态。

移动端/低性能设备可降低高细节、阴影和后处理，减少非必要动画，但必须保留核心交互并给出明确反馈。

# 13. 推荐执行阶段与验收标准

## PHASE 0 — 接管与现状审计
读取 V3.0、文档和代码；启动项目；审计模型装配、运动、拆解和 UI；建立缺陷清单。
**验收：** 有基于真实代码与运行结果的状态报告。

## PHASE 1 — 核心身份与状态统一
统一零件 ID、选中状态、模型/装配/零件层级、运动/拆解/剖切状态及互斥规则。
**验收：** 零件列表、模型网格、信息面板和关系系统准确对应。

## PHASE 2 — Mechanism Graph
建立关系 Schema、注册与校验、连接锚点、关系可视化，并为 V8 标注关键关系。
**验收：** 系统知道曲轴、连杆、活塞之间的关系，而不只是知道网格存在。

## PHASE 3 — 统一运动学引擎
统一时间轴、播放/暂停/重置、速度控制、运动组件注册和生命周期；实现 V8 标杆运动。
**验收：** 运动连贯、稳定、可控，暂停和复位正确。

## PHASE 4 — 交互式结构探索
零件隔离、隐藏/显示、局部聚焦、关系追踪、剖切、拆解和复位联动。
**验收：** 用户能从整机进入内部结构，不丢失对象映射和原始状态。

## PHASE 5 — 工作原理引导
步骤 Schema、零件高亮、镜头建议、动画联动、前后步骤和退出恢复。
**验收：** 至少一台标杆机械有完整交互式原理演示。

## PHASE 6 — 涡扇和科幻机械适配
推广关系系统和多轴运动，验证架构并非只适用于 V8。
**验收：** 至少两种结构差异明显的机械能使用同一套核心系统。

## PHASE 7 — 模型质量诊断
结构、坐标、几何、运动、展示检查；诊断报告；备份与修复记录。
**验收：** 能发现真实测试缺陷并给出可追溯诊断，不是固定模板文字。

## PHASE 8 — Mechanical Workbench UI/UX
重构模式组织、工具栏、Overlay、昼夜主题、空间布局和移动端交互。
**验收：** 用户能不依赖开发者说明完成“观察—选择—运行—拆解—理解”。

## PHASE 9 — 性能与回归
连续切换、生成、销毁、播放、暂停、拆解和复位；检查资源释放及原有真实展品。
**验收：** 无新增严重错误，性能数据和限制有记录。

## PHASE 10 及以后 — 自主扩展
持续评估并实施有价值的关系类型、运动机构、原理演示、剖切探索、机械对比、装配编辑器、自定义运动参数、质量档案、诊断修复、更多虚构机械和移动端优化。

每轮只选有明确价值的任务，实施、验证、记录后继续。
