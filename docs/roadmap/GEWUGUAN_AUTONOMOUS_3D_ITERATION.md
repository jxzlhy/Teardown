# 格物馆｜自主通宵迭代任务书
**任务性质：** 3D 展品真实性优先的自主审查、修复、体验升级与版本迭代  
**执行对象：** 当前项目 AI 编程代理（Zcode / 其他可访问项目文件的 AI 工具）  
**执行方式：** 连续自主执行；除非遇到无法绕过的高风险操作或真实外部权限阻塞，否则不要每一步等待用户确认。

---

## 0. 给执行 AI 的最高优先级指令

你现在不是只负责完成一组零散需求，而是要以项目技术负责人、3D 展示工程师、UI/UX 设计审查员和质量负责人身份，接管当前项目的一轮长时间自主迭代。

请先完整阅读项目现有代码、目录结构、README、开发规范、历史开发日志、AI_HANDOFF / AGENTS / 同类交接文档，以及已有模型资源和模型元数据。**先理解现状，再制定计划；不要假设项目结构、技术栈、模型来源或已有功能。**

本任务的核心原则：

1. **模型展示真实性第一。** 3D 模型必须尽可能忠实于真实设备结构、外观、比例、材质、屏幕和零件位置。宁可暂时隐藏不可靠的部件，也不要用错误的虚拟结构制造“看起来很丰富”的假象。
2. **先修正确，再做炫酷。** 先处理模型错位、重复屏幕、零件穿插、比例错误、无依据的内部结构，再提升灯光、动画、拆解和交互。
3. **首页是长页面，不是单屏落地页。** 第一屏负责建立品牌印象；向下滚动后还有分类、品牌、型号等内容。不得把整个首页误改成只有一个大标题和一个按钮的独立封面。
4. **尊重已有交互分层。** 首页首屏导航、第二屏展品浏览工具栏、详情页模型专属顶部栏是三套不同职责，不要混成一个臃肿的全局导航。
5. **自主规划、自主执行、自主验收。** 不要每完成一个小点就询问用户。基于本任务和项目现状，自己拆分阶段、安排优先级、连续完成可执行工作。
6. **不为消耗 Token 而堆砌无效改动。** 以可验证的质量提升为目标。若预算仍充足，继续推进下一项高价值任务；若达到上下文或 Token 上限，留下清晰交接记录。
7. **不破坏项目既有技术路线。** 优先复用当前技术栈、组件、资源和约定。任何大规模重构都必须先论证必要性，并采用可回滚的小步方式。
8. **不得伪造验收结果。** 没有实际运行、构建或浏览器验证的项目，必须明确标注“未验证”及原因。

## 1. 项目接管与基线盘点

### 1.1 必须先做的检查

- 阅读项目根目录说明、README、开发规范和所有交接文档。
- 检查 package.json、锁文件、构建脚本、运行命令、框架版本、3D 引擎及相关依赖。
- 梳理首页、分类/品牌/型号列表、模型详情页、总览弹窗、搜索/视图切换/收藏等现有页面和组件。
- 梳理所有 3D 模型资源：格式、来源、授权/许可说明、文件大小、网格层级、材质、动画、坐标轴、缩放比例、零件命名及可拆解程度。
- 记录当前已知问题、潜在回归风险和无法确认的事项。
- 先运行现有项目，保存初始截图或录屏（项目支持时），建立改动前基线。

### 1.2 建立问题清单

每个问题记录：
- 问题 ID；
- 所属页面/模型；
- 复现步骤；
- 当前表现；
- 正确预期；
- 严重程度（P0/P1/P2/P3）；
- 修复方案；
- 验证方法；
- 状态与证据。

优先级定义：
- **P0：** 模型结构明显错误、重叠、错位、遮挡核心展品、页面无法使用或构建失败。
- **P1：** 主要展示体验问题、关键交互异常、首页信息层级严重不清。
- **P2：** 动效、灯光、材质、细节、性能等体验优化。
- **P3：** 非关键装饰、实验性效果和未来扩展。

## 2. 第一优先级：3D 展品真实性与模型质量专项

这是本轮工作的核心，不允许被新增模型或视觉特效抢占。

### 2.1 屏幕内容重复/错误叠加

重点排查用户指出的情况：例如某款 iPhone 12 模型本身已经带有真实屏幕画面，项目又额外叠加了一层虚拟屏幕 UI，导致画面重叠；甚至额外 UI 并不是该型号真实的系统界面。

执行要求：
- 检查模型原始材质、贴图、屏幕网格、发光材质和项目额外创建的屏幕 DOM/Canvas/纹理层。
- 判断屏幕画面究竟来自模型原始贴图，还是项目运行时叠加。
- 如果模型原生屏幕贴图已经正确，默认不要再叠加第二层虚拟 UI。
- 如果原生屏幕贴图缺失或不可用，才考虑使用独立屏幕内容；必须确保它与机型、时代、屏幕比例、圆角、刘海/挖孔等相符。
- 为屏幕内容建立明确的配置开关，避免同一模型同时启用两套屏幕显示方案。
- 不得把现代 iOS 界面随意放到不匹配的老机型上，也不得将不确定的界面冒充真实原厂界面。
- 对无法确认的屏幕内容，宁可使用克制的中性待机画面或关闭叠加层，并在元数据中标注。

建议验收：
- 旋转模型，从正面、斜侧面、近距离观察屏幕。
- 确认没有双层文字、双层图标、错位边缘、闪烁或 z-fighting。
- 确认不同机型不会错误共用不匹配的屏幕 UI。

### 2.2 裸露零件、内部结构错位

重点排查用户指出的情况：有些模型内部零件裸露在外，且不在真实位置，可能出现主板、电池、摄像头、镜头、传感器、扬声器、连接器等漂浮、穿模、比例不对或装配关系错误。

执行要求：
- 逐个检查模型层级和零件坐标，区分原始模型自带结构与代码运行时额外添加的装饰件。
- 检查父子层级、局部坐标/世界坐标、旋转、缩放、枢轴点、单位换算、模型原点和轴向。
- 检查模型加载后是否重复应用了变换，是否有额外偏移或错误的自动居中逻辑。
- 对每个零件核对其应处于的真实区域、朝向、尺寸和装配关系。
- 对没有可靠依据的零件，不要随意放置在模型外侧充当“内部结构展示”。
- 对暂时无法修正的部件，优先隐藏、禁用拆解或标记为待核实，不要保留明显错误的展示状态。
- 拆解动画必须沿合理方向移动，拆开后各部件仍能对应其原始装配位置；复位后必须准确回到初始位置。
- 不得为了视觉效果任意改变真实结构。

### 2.3 建立模型质量分级

建议每个模型使用统一质量状态：
- A：结构、比例、材质和主要部件均经过核对，可作为标准展品。
- B：外观可信，部分内部细节或材质仍待核实。
- C：仅适合概念展示，不应启用真实拆解或内部结构讲解。
- D：存在明显错误，暂时下架或隐藏问题部件，修复后再展示。

每个模型维护元数据：设备名称、型号、年份、模型来源、许可信息、结构完整度、屏幕方案、内部结构可信度、拆解能力、已知问题、核验状态。不得编造来源或真实性证明。

### 2.4 模型展示统一验收标准

每个重点模型至少检查：
- 正面、背面、左右侧面、顶部、底部；
- 近景和远景；
- 默认装配状态；
- 拆解状态（若支持）；
- 拆解后复位；
- 屏幕/贴图是否正确；
- 零件是否穿模、漂浮、错位；
- 材质是否丢失、发黑、过曝或闪烁；
- 加载性能与移动端帧率；
- 触控旋转、缩放、拖动是否正常。

## 3. 首页与导航体验优化

### 3.1 首页结构理解

首页是一个可持续向下滚动的长页面。第一屏只是首页的首屏展示，不是整个首页。下方还有模型分类、类型、品牌、型号等内容。所有优化都必须保留并尊重这一信息架构。

### 3.2 第一屏：品牌印象区

目标：让用户进入时迅速感受到“格物馆”的气质，而不是被巨大文字占据视线。

建议：
- “格物馆”品牌文字不宜过大，不要成为压住模型的主视觉。
- 第一屏应突出一个有代表性的 3D 展品或模型视觉。
- 标题、简短介绍和引导信息保持克制，避免大段说明。
- 让展品成为视觉焦点，品牌文字负责识别，背景/灯光/空间氛围负责烘托。
- 第一屏顶部栏可以保留知识星图、技术编年等入口，但视觉权重应低于主展品。
- 不要把分类、搜索、收藏等第二屏工具全部塞入首屏。
- 进入按钮并非强制项；如果页面本身自然向下滚动，避免为了形式增加无意义按钮。

### 3.3 首屏顶部栏与滚动后的工具栏

当前已有交互逻辑：
- 第一屏顶部栏：展示品牌/其他全局入口，例如“知识星图”“技术编年”。
- 向下滚动后，第二屏的浏览工具栏出现并吸顶。工具栏包含搜索、列表/网格展示切换、收藏等功能。
- 当前滚动吸顶行为已经存在，不要无理由推翻。

优化方向：
- 首屏顶部栏只服务首屏，向下滚动后允许其自然离开视野，不要求始终固定占位。
- 第二屏工具栏继续承担展品浏览操作，并在滚动到对应区域时吸顶。
- 首屏顶部栏离场与第二屏工具栏吸顶之间，过渡应自然，不应出现两栏长时间重叠、闪跳或空白断层。
- 可优化吸顶时的背景、模糊、阴影、边框和高度，但保持轻量。
- 搜索、视图切换、收藏等工具必须保持清晰可用，不能为了视觉简洁而降低可发现性。

### 3.4 模型详情页顶部栏

详情页顶部栏与首页完全不同，保持独立：
- 左侧显示当前模型名称。
- 右侧显示“总览”入口/图标。
- 点击总览后，以弹窗或项目当前合适的浮层形式展示模型资料，例如简介、发布时间、主要设计者/主设等。
- 不要将首页的知识星图、技术编年等全局入口复制到模型详情页。
- 总览信息应清楚、克制、易读，不遮挡模型主要展示区域。
- 缺少可靠资料的字段应省略或标注未知，不要编造。

### 3.5 首页验收

- 从页面顶部开始连续滚动，确认长页面内容顺序正常。
- 首屏顶部栏离场合理，第二屏工具栏按预期吸顶。
- 搜索、列表/网格切换、收藏操作均可正常使用。
- 进入模型详情页后，顶部栏只显示模型名称与总览入口。
- 总览弹窗内容准确，关闭方式明确。
- 移动端不同屏幕尺寸下不遮挡状态栏、安全区和核心展品。

## 4. 新增 3D 展品：优先试点，而不是批量凑数

本轮允许新增 3D 模式与模型，但必须以质量为前提。建议先选 1–2 个代表性机械展品作为试点，完成完整体验后再决定扩展。

### 4.1 试点 A：V8 发动机

目标：建立一个可观察、可拆解、可演示运动关系的 V8 发动机展品。

建议功能（以资源和技术可行性为准）：
- 完整装配状态：缸体、缸盖、气门机构、曲轴、连杆、活塞、进排气系统等主要结构。
- 爆炸拆解视图：主要部件沿合理方向分层展开，避免随意漂浮。
- 关键运动演示：曲轴旋转、活塞往复、连杆运动；若模型和性能允许，再扩展气门机构联动。
- 结构讲解：点击部件显示名称、功能、工作原理。
- 模式切换：完整视图、拆解视图、工作原理演示。
- 一键复位、暂停/播放、旋转/缩放和视角预设。
- 动画必须遵循机械运动关系，不能只做无意义的整体旋转。

### 4.2 试点 B：星型/径向活塞发动机

用户提到的“行星发动机”可能是指星型/径向发动机（Radial Engine）。实施前先核实用户想要的具体类型；若项目资源中已有“行星齿轮机构”或其他行星机械模型，也可作为独立展品，但不要混淆概念。

星型/径向发动机可考虑：
- 气缸围绕中心曲轴布置；
- 主连杆与副连杆结构；
- 活塞往复与曲轴旋转关系；
- 爆炸拆解和部件标注；
- 工作循环的简化动画；
- 结构剖视/透明外壳模式（若真实模型支持）。

### 4.3 新展品资源标准

- 优先寻找完整拆解 / exploded view / teardown 类型资源。
- 优先 GLB/ glTF 等运行时易接入格式；具体以项目当前引擎支持为准。
- 优先选择独立网格清晰、零件命名合理、结构可识别的资源。
- 必须核实授权许可、来源和可否用于项目展示。
- 不能只因为模型外观炫酷就直接集成。
- 资源不满足拆解标准时，可先作为静态模型候选，不要伪装成完整可拆解模型。
- 优先选人气高、结构清晰、可解释性强的模型。

### 4.4 新展品验收

- 装配状态结构正确；
- 拆解方向与层级合理；
- 动画运动关系正确；
- 部件名称和讲解准确；
- 复位无偏差；
- 触控操作流畅；
- 移动端性能可接受；
- 授权与来源记录完整。

## 5. 3D 交互、视觉与性能升级

在模型正确性达标后，再开展以下增强：

- 优化环境光、主光、轮廓光、阴影和地面接触感。
- 材质表现应服务真实质感，避免过度金属化、塑料感或过曝。
- 优化模型默认镜头、旋转速度、缩放边界、阻尼和自动旋转策略。
- 为重要模型提供正面、背面、侧面、内部等视角预设。
- 拆解/复位使用平滑且可中断的过渡。
- 增加部件热点、选中高亮、信息面板等交互，但避免满屏标记。
- 检查纹理尺寸、模型面数、阴影开销、加载策略和资源释放。
- 优先保证手机端流畅，不以桌面端效果作为唯一标准。
- 对低性能设备提供合理降级：降低阴影质量、关闭高开销效果、减少同时运行的动画。
- 如果项目已有白天/夜晚模式或环境切换能力，可评估优化；不要为增加功能而牺牲模型真实性和性能。

## 6. 自主执行与版本迭代机制

你必须自行规划版本，不要把所有工作塞进一个不可控的大提交。可根据项目实际情况调整阶段名称，但建议按以下顺序执行：

### Phase 0 — 接管与审计
完成项目阅读、运行基线、结构盘点、问题清单、风险识别。

### Phase 1 — P0 模型错误修复
优先处理屏幕叠加、屏幕内容不匹配、零件裸露错位、模型变换错误、材质异常等问题。

### Phase 2 — 核心模型质量体系
建立模型元数据、质量分级、统一验收标准和问题追踪机制。

### Phase 3 — 首页与导航体验
优化第一屏视觉层级、首屏导航、第二屏吸顶工具栏、详情页顶部栏与总览弹窗；保留原有长页面结构。

### Phase 4 — V8 发动机试点
完成资源筛选、结构审查、集成、拆解、运动演示和移动端验收。

### Phase 5 — 星型/径向发动机或第二个机械试点
确认类型后实施，确保质量不低于 V8 试点。

### Phase 6 — 3D 展示体验升级
灯光、材质、镜头、热点、动画、性能和移动端适配。

### Phase 7 — 全站回归与版本整理
完整回归首页、分类、品牌、详情、总览、搜索、视图切换、收藏、知识星图、技术编年及已有展品。

### Phase 8 — 自主规划下一版本
基于实际成果和剩余问题，提出下一版本目标并直接执行其中风险可控、价值明确的任务。不要停下来只给计划。

每个 Phase 完成后：
1. 自行检查完成标准；
2. 运行相关测试、构建和页面验证；
3. 更新问题清单；
4. 记录未完成事项和原因；
5. 继续下一个阶段。
