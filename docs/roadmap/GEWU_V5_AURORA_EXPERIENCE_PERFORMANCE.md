# 01. 本次任务的核心目标

GEWU 已经具备一定的产品功能、3D 模型资产和交互能力，但目前存在一个明显的问题：

**功能逐渐丰富，视觉表现和交互体验却没有同步进化。**

目前需要重点解决：

1. 整体 UI 视觉表现不够高级，缺乏视觉记忆点。
2. 3D 展示区域缺乏沉浸感和空间层次。
3. 交互方式偏传统，缺少自然、流畅、有反馈的操作体验。
4. 已安装大量 UI/UX、Design、QA 等 Skills，但没有充分发挥它们的价值。
5. 页面、工具栏、面板之间的设计语言可能不够统一。
6. 随着模型、纹理、组件、动画和功能不断增加，整体运行流畅度下降。
7. GLB/GLTF 模型加载速度、模型切换速度、内存管理和 GPU 资源管理需要进一步优化。

本次升级必须围绕两个核心方向：

**AURORA EXPERIENCE：打造更高级、更炫酷、更自然的交互体验。**

**AURORA PERFORMANCE：让丰富的 3D 内容依然能够快速加载、流畅运行。**

不要把本次任务理解为简单的 CSS 美化或性能小修小补。

本次允许对 UI 结构、组件体系、交互流程、动画系统和模型加载架构进行必要的优化重构，但必须以实际审查结果为依据。

# 05. P2：AURORA DESIGN SYSTEM

重新建立统一的 GEWU 视觉设计规范。

目标：

高级、精密、科技感、沉浸感、空间感。

不能只是普通的后台管理系统，也不能过度使用廉价霓虹、过量渐变和玻璃拟态。

## 5.1 全局视觉体系

统一：

- 字体体系。
- 字号层级。
- 行高。
- 间距。
- 圆角。
- 边框。
- 阴影。
- 背景层级。
- 玻璃面板。
- 图标。
- Tooltip。
- 动画时间。
- 缓动曲线。
- 交互状态。

所有设计变量必须集中管理，避免不同模块各自定义一套。

## 5.2 深色主题

重点打造高品质深色数字展馆。

要求：

- 深色背景具有空间层次。
- 3D 模型始终是视觉中心。
- 面板有合理的透明度和模糊效果。
- 光影与模型材质协调。
- 选中状态明显但不过度发光。
- 文字层级清楚。
- 面板不遮挡关键模型区域。

## 5.3 白天主题

不能只是把黑色替换成白色。

需要单独设计：

- 明亮展馆环境。
- 面板透明度。
- 文字对比度。
- 展台材质。
- 模型环境光。
- 高亮和选中反馈。

昼夜切换不得导致模型重新加载、相机复位或当前交互状态丢失。

## 5.4 组件体系

统一设计：

- Button
- IconButton
- Toolbar
- Tooltip
- Popover
- Dropdown
- Tabs
- Drawer
- Dialog
- SidePanel
- Inspector
- Search
- Loading
- Progress
- Empty State
- Toast
- Context Menu

禁止同一种功能在不同页面出现明显不同的视觉风格。

# 06. P3：3D 展示与交互体验全面升级

这是 GEWU 最核心的产品体验。

不能让用户感觉自己只是在操作一个普通 Three.js 模型查看器。

## 6.1 展示舞台

重点改进：

- 展台设计。
- 地面。
- 环境光。
- 背景。
- 阴影。
- 反射。
- 相机视角。
- 景深与视觉层次。
- 模型进入舞台的过渡动画。

根据模型类别提供合理的展示环境。

例如：

手机、相机、无人机、汽车、飞机、机械装置、工业设备可以有不同的展示模板。

但不能为了展示效果影响真实模型颜色、结构和材质的准确性。

## 6.2 模型选中交互

实现：

- Hover 高亮。
- Click 选中。
- 选中轮廓。
- 当前零件聚焦。
- 其他零件适当弱化。
- 选中信息面板同步更新。
- 平滑镜头移动。
- 一键恢复总览。

避免模型选中与屏幕位置出现偏移。

避免高亮轮廓错误、闪烁和遮挡。

## 6.3 拆解与组装

优化：

- 完整拆解。
- 分组拆解。
- 单件隔离。
- 单件隐藏。
- 单件显示。
- 拆解进度。
- 组装进度。
- 平滑过渡。
- 暂停。
- 继续。
- 复位。

所有动画必须尊重真实模型的层级和零件关系。

不得为了动画效果擅自创造真实机械零件或改变真实结构。

## 6.4 零件导航

重新设计零件导航：

- 树形结构。
- 分类。
- 搜索。
- 当前零件状态。
- 零件数量。
- 分组展开收起。
- 隐藏和显示。
- 聚焦。
- 与 3D 场景双向联动。

需要考虑大型模型拥有大量 Mesh 时的导航性能。

不能一次性为数千个零件创建大量不必要的复杂 DOM。

## 6.5 工具栏

重点解决：

- 工具按钮视觉单调。
- Tooltip 遮挡。
- 菜单层级混乱。
- 视角菜单不合理。
- 工具过多导致拥挤。
- 移动端操作困难。

提供合理的分组和快捷操作。

## 6.6 镜头系统

优化：

- 轨道旋转。
- 缩放。
- 平移。
- 自动对焦。
- 视角预设。
- 总览。
- 前后左右视图。
- 自由视角。
- 平滑过渡。
- 镜头状态恢复。

不能在镜头切换时造成明显跳变。

## 6.7 沉浸式反馈

可以探索：

- 轻量级粒子。
- 精细的选中反馈。
- 空间化提示。
- 动态环境光。
- 精致的加载动画。
- 细腻的过渡。
- 可选交互音效。

所有效果都必须有性能预算。

不要为了炫酷而无节制地增加粒子、Bloom、后处理和实时阴影。

# 08. P5：模型加载性能专项

这是第二个核心目标。

GEWU 已经拥有大量模型资产，不能继续通过简单增加资源的方式堆叠功能。

必须优化整个模型加载链路。

## 8.1 加载流程分析

检查：

用户进入页面  
→ 选择模型  
→ 获取模型资源  
→ 下载 GLB  
→ 解析 GLTF  
→ 解码几何数据  
→ 解码纹理  
→ 创建材质  
→ 创建场景对象  
→ 首次渲染  
→ 完全可交互

明确每个环节的实际耗时。

不要把下载时间和解析时间混为一谈。

## 8.2 加载优化

根据项目实际架构实施：

- 模型预加载策略。
- 延迟加载。
- 按需加载。
- 并发加载控制。
- 加载队列。
- 解析任务调度。
- DRACO 解码优化。
- Meshopt 优化。
- KTX2 / Basis 纹理压缩。
- 纹理尺寸优化。
- Mipmap 策略。
- 模型缓存。
- 加载失败恢复。
- 重复资源复用。

不要盲目对所有模型执行同一种压缩方案。

必须验证材质、透明度、法线、金属度、粗糙度、动画和零件层级没有被破坏。

## 8.3 加载体验

实现阶段式加载反馈：

- 正在获取模型。
- 正在解析模型。
- 正在加载纹理。
- 正在构建场景。
- 正在准备交互。
- 加载完成。

如果无法获取真实进度，不得伪造百分比。

可使用明确标注的阶段进度或不确定进度动画。

切换模型时，合理保留当前模型，避免出现长时间空白。

## 8.4 模型缓存

研究：

- 内存缓存。
- IndexedDB 持久缓存。
- 重复模型复用。
- 资源缓存失效。
- 缓存容量限制。
- 缓存清理策略。

必须防止缓存无限增长。

# 09. P6：Three.js 渲染性能优化

全面检查：

## 9.1 Draw Calls

- 检查每个模型的 Draw Calls。
- 检查材质数量。
- 检查 Mesh 数量。
- 检查重复对象。
- 评估 InstancedMesh。
- 评估合理合批。

注意：真实拆解模型必须保留必要的独立零件结构，不能为了减少 Draw Calls 破坏交互能力。

## 9.2 LOD

研究合理的多级细节方案：

- 高质量展示模型。
- 中等质量模型。
- 低质量预览模型。

根据设备能力和相机距离动态调整。

如果原始资产没有 LOD，需要评估自动生成的收益和结构损失，不能盲目执行。

## 9.3 视锥剔除

- 不渲染不可见对象。
- 合理管理大型模型。
- 避免不必要的场景遍历。
- 优化大量 Mesh 的更新成本。

## 9.4 渲染循环

检查：

- 是否存在无意义的持续渲染。
- 静止状态是否仍然高频更新。
- 动画结束后是否能合理降低渲染频率。
- UI 状态更新是否导致整个 3D 场景重复刷新。
- 后处理是否过度消耗性能。

## 9.5 GPU 资源释放

重点检查：

- Geometry.dispose()
- Material.dispose()
- Texture.dispose()
- RenderTarget.dispose()
- WebGLRenderer 资源管理。
- 模型卸载。
- 路由切换。
- 页面销毁。
- 重复加载。
- HMR 开发环境下的资源泄漏。

不能简单 dispose 所有资源。

必须考虑共享材质、共享纹理和资源引用关系。

## 9.6 移动端优化

重点：

- DPR 控制。
- GPU 能力检测。
- 纹理预算。
- 模型复杂度预算。
- 后处理降级。
- 阴影降级。
- 粒子数量限制。
- 动画帧率策略。
- 触控响应。
- 设备内存压力处理。

根据实际设备能力制定档位。

不要假设所有用户都有高端显卡。

# 10. P7：性能监测和自动化基准

建立 GEWU Performance Benchmark。

至少监测：

| 指标                 | 说明                             |
| -------------------- | -------------------------------- |
| Download Time        | 模型下载耗时                     |
| Parse Time           | GLB/GLTF 解析耗时                |
| Texture Time         | 纹理处理耗时                     |
| Time To First Render | 首次渲染时间                     |
| Time To Interactive  | 首次可交互时间                   |
| Model Switch Time    | 模型切换耗时                     |
| FPS                  | 渲染帧率                         |
| Frame Time           | 帧耗时                           |
| Draw Calls           | 绘制调用次数                     |
| Triangle Count       | 三角形数量                       |
| Mesh Count           | Mesh 数量                        |
| JS Heap              | JS 堆内存                        |
| GPU Memory           | GPU 显存估算或可用的实际监测指标 |

注意：

浏览器并不一定能直接提供精确 GPU 显存数据。

如果只能估算，必须标注估算值，不得把估算当成真实测量。

选取不同复杂度的代表性模型建立测试集。

必须进行优化前后对比。

# 15. 设计质量要求

请始终记住：

GEWU 不是普通后台管理系统。

它是一个以真实 3D 产品和机械结构为核心的数字展馆。

UI 必须服务于模型。

交互必须服务于探索。

动画必须服务于理解。

性能必须支撑体验。

不要为了所谓的科技感加入没有实际意义的装饰。

不要为了视觉效果牺牲模型真实性。

不要为了性能破坏零件独立性。

不要为了代码整洁而无必要地推翻稳定架构。

最终目标：

让用户进入 GEWU 时，第一眼就能感受到视觉品质；操作模型时，能感受到自然、精致的反馈；面对复杂机械模型时，仍然可以流畅地探索、拆解和交互。
