## 二、总分与判语

### **75 / 100 —— 内容资产驱动的实验型精品，工程底子扎实，产品化收尾未跟上功能扩张**

- **75 分的含义**：高于"能跑的 demo"一档（有 CI 级自研测试、构建期生成、真实降级策略），但**不具备公开发布条件**（许可未收口 + 移动端/集显存在崩与卡的真实路径 + 馆内仍有占位展品）。
- **它不是 60 分**：因为基线全绿（build 2.74s ✓ / lint 0 错 ✓ / smoke 32 项 ✓ / prod audit 0 漏洞 ✓），且分包、缓存、竞态防护、诚实降级这些细节做到了多数中型项目不做的位置。
- **它不是 85 分**：因为两个 P0 是"真实用户点进去会失败"的级别，且数字一致性（117/110/104/104）与占位展品属于**可信度硬伤**——对一个以"严谨考据"为卖点的博物馆而言，这类问题的伤害大于功能缺失。

## 三、分维度详评（含加分项，避免只报缺陷）

### UI 视觉 72
概念清晰且执行有品位：双厅语义、三层字体（名字/数据/操作）、光晕而非投影的阴影策略、`color-mix` 派生梯度随展品主色换肤——这些是**设计系统级别**的思考，不是套模板。扣分在"最后一公里"：日厅是逐条补丁堆出来的（165 条覆盖），一旦某个 class 没补到就是 1.16:1；字符当图标让 28 个正式控件在不同平台字形漂移；24 种字号 + 14 种 z-index 说明"层级"仍靠肉眼调。

### UX 交互 78
优点非常实在：空态有出路文案、未标定诚实显示 `u · 未标定`、无数据面板直接隐藏、28 个 dock 按钮全带 aria-label、首访有引导卡。扣分在**信息架构**：117 件藏品的核心动作是"找到那件"，而搜索被放在第三屏；以及移动端导视在文案变长时把一级功能按钮挤出屏幕。

### 产品功能 76
功能广度（拆解/剖切/X光/隔离/测量/逐步装配/导览/TTS/评分/收藏/星图/编年/对比/锻造所+GLB导出+配置分享）**超过 iFixit 与 Sketchfab 的单点能力**。但广度已明显跑赢深度：mech 2.6%、realSizeMM 0.9%、assembleStep 1.7% 意味着三个已上线的工具对 98% 展品是降级态；两台 TODO 展品说明"入馆流程"缺最后一道闸。

### 代码质量 78 / 架构 80
`loadSeq`+`AbortController`、`disposeDevice` 成对释放、`getState` 只出标量、引擎实例不进响应式、全库无 deep watch——这些是对的方向。架构上"UI 壳 / 引擎 / 声明式配置 / 构建期生成"四层划分清晰且**适合这个规模**，不需要重写。扣分集中在生命周期收尾（`__ENGINE`、PMREM）与"调试全局即公共 API"的未记账债务。

### 性能 70（最分裂的一维）
**JS 侧近乎满分**：大厅零 three（实测 canvas 0）、设备配置按台懒加载（实测只请求 1 份）、gzip 首屏 42.5KB、Cache Storage 存原始字节 + 512MB LRU + 并发单飞。**资产侧接近失控**：14 台 ≥4096 纹理（最贵一台估算 3.26GB 显存）、9 台 >50 万三角却**没有 BVH 加速拾取**。这一维的 70 分不是"慢"，而是"最贵的展品有崩的风险，且崩在默认交互路径上"。

### 安全 85
纯前端 + 无 v-html/eval + 深链白名单 + prod 0 漏洞，攻击面控制得比多数后端项目还好。真正的问题不是传统安全而是**许可合规**：5 台明确风险许可随 dist 分发 + 35 台无 `modelCredit` 字段（多数在 `source:` 里有出处，但 lint 不看这个字段）。

### 兼容与响应式 74
三断点覆盖到 390×844，懒加载/sheet/步进器等移动细节到位；但触控热区、safe-area、导视溢出三件事都还差一轮，且**从未在真 iOS/Android 上跑过**（项目自己也记为待办）——在没有真机证据前，这一维不能给到 80。

### 可维护性与文档 72
文档文化是这项目的**显著优点**（LOG 141KB、METRICS 只记可复现测量、BACKLOG 带验证方式、分阶段档案、AI 接管须知）。但"文档多"不等于"文档准"：本次实测发现 4 处数字互相打脸、DESIGN_SYSTEM 与代码取值漂移、AGENTS §4 的命令清单与 package.json 不完全一致。生成物过期是纪律问题，不是能力问题——修起来最便宜，伤害却最大。

### SEO 与无障碍 52（最低维）
无障碍的"骨架"其实比一般项目好（reduced-motion 双层、alt 118/118、aria-label 齐、Tab 可用），但**语义地标缺失 + 对比度大面积不达标 + 焦点环被主动关掉 + aria-live 为 0**，任何一条被无障碍审查者拿到都是明确不合格项。SEO 上 hash SPA 决定了设备页不可索引，这是产品选择而非疏忽，但缺 `og:image` 让"分享即裸链"，属于可低成本修复的传播损失。

## 五、评分局限（诚实声明）

1. 帧率与耗时在 load average 3.6–7.4 的机器上测，是**下界**；真机空闲机会更好，但显存与三角形数量是硬事实，不受此影响。
2. 对比度扫描以"最近不透明祖先背景"为底，**未计算文字压在缩略图/3D 画布上的情形**（这类会偏乐观）；数值口径为 WCAG 相对亮度公式。
3. 显存为 RGBA8+MIP（×1.34）估算，实际 GPU 可能因压缩纹理/格式差异而不同；未做真机 `WEBGL_debug_renderer_info` 级别的显存计量。
4. 主观审美项（构图、留白、层级）以截图 + 具体位置给出，属可讨论判断，不与"AA 不达标"这类客观缺陷混在同一权重。
5. 许可合规只做了**代码内证据**的交叉比对，未逐台访问上游资产页面复核当前许可（许可可能被作者追溯更改），该项标为需人工。

### 判语更新
75 → **78**。变化不在"分数"，在**性质**：两条会让真实用户"崩/卡"的 P0 与三条可信度 P1 已关闭且有量化证据；项目从"不具备公开发布条件"变成"跑一条 `npm run build:release` 即具备可发布口径（许可人工复核除外）"。
